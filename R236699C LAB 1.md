# Lab 1: Empirical Validation of the Master Theorem and Recurrence Solving

## Abstract

This report solves four divide-and-conquer recurrences analytically (Master Theorem where applicable, recursion-tree/substitution otherwise), proves each closed form by induction, and then tests those closed forms against two kinds of empirical measurement: an abstract recursive simulator that counts operations purely from the recurrence's own formula, and real algorithm implementations (merge sort, a deliberately brute-force combine step, pre-Karatsuba multiplication, and a recursive binary search) with no memoization. The abstract simulation matches theory exactly everywhere, by construction, so it serves mainly as a correctness check on the proofs; the real implementations deviate from theory in three distinct, explainable ways — a shrinking lower-order term (merge sort), a flat constant-factor offset caused by a mismatch between the recurrence's $f(n)$ and what the real combine step actually costs (the two $\Theta(n^2)$ recurrences), and, in one case, a genuine implementation bug that at first looked like a legitimate deviation finding and had to be distinguished from one. Repeated wall-clock trials show operation counts are perfectly reproducible while timing is not, which motivates the final synthesis: a modified recurrence combining an uneven 1:3 split with a cache-miss penalty, solved rigorously via a sandwich argument to be $\Theta(n\log n)$ regardless of where the cache threshold falls, with the practical constant left as an approximation.

## Task 1: Analytical Solutions

## 1. Introduction and Objectives

Asymptotic analysis provides the mathematical foundation for evaluating algorithm efficiency. However, theoretical bounds often rely on simplifying assumptions, such as assuming unit-cost operations and ignoring hardware context. The objectives of this lab are:

1. Derive closed-form solutions and asymptotic bounds for four target divide-and-conquer recurrences.
2. Formally prove all derived bounds using mathematical induction.
3. Design and implement a benchmark harness that counts basic computational operations directly without reliance on wall-clock timing.
4. Compare empirical operation growth against theoretical curves for input sizes $n \in [2^1, 2^{20}]$.
5. Analyze sources of divergence between theory and empirical measurement.
6. Synthesize a realistic recurrence model incorporating real-world system constraints.

## 2. Analytical Solutions and Induction Proofs

The general form of a divide-and-conquer recurrence is given by:

$$T(n) = a T\left(\frac{n}{b}\right) + f(n)$$

where $a \ge 1$ represents the number of subproblems, $b > 1$ is the division factor, and $f(n)$ is the cost of work performed outside recursive calls.

### Assumptions and Method

Throughout, $n$ is a power of 2, written $n = 2^k$, and the base case is $T(1) = 1$. All logarithms are base 2. This matches the experimental range $n = 2^1$ to $2^{20}$ used later in the lab.

For $T(n) = aT(n/b) + f(n)$ we use the Master Theorem, which compares $f(n)$ with $n^{\log_b a}$ (the leaf work). Case 1: $f(n)$ polynomially smaller gives $\Theta(n^{\log_b a})$. Case 2: if $f(n) = \Theta(n^{\log_b a} \log^k n)$ for some $k \ge 0$, the result is $\Theta(n^{\log_b a} \log^{k+1} n)$. Case 3: $f(n)$ polynomially larger, plus the regularity condition $a f(n/b) \le c f(n)$ for some $c < 1$, gives $\Theta(f(n))$.

---

### Recurrence 1: $T(n) = 2T(n/2) + n$

**Master Theorem.** Here $a = 2$, $b = 2$, so $n^{\log_2 2} = n$. Since $f(n) = n = \Theta(n)$, this is **Case 2** (extended form with $k = 0$, because $f(n)$ has no logarithmic factor).

**Result:** $T(n) = \Theta(n \log n)$.

**Exact solution:**

$$T(n) = n \log_2 n + n$$

**Proof by induction on $k$ (where $n = 2^k$).**

- **Base case:** $T(1) = 1$, and $1 \cdot \log_2 1 + 1 = 0 + 1 = 1$.
- **Inductive hypothesis:** assume $T(n/2) = \frac{n}{2}\log_2\frac{n}{2} + \frac{n}{2}$.
- **Inductive step:**

$$
\begin{aligned}
T(n) &= 2T(n/2) + n \\
&= 2\left[\tfrac{n}{2}(\log_2 n - 1) + \tfrac{n}{2}\right] + n \\
&= n\log_2 n - n + n + n \\
&= n \log_2 n + n.
\end{aligned}
$$

**Conclusion.** Since $n \log n \le n \log n + n \le 2 n \log n$ for all $n \ge 2$, we have $T(n) = \Theta(n \log n)$.

---

### Recurrence 2: $T(n) = 2T(n/2) + n^2$

**Master Theorem.** Here $a = 2$, $b = 2$, so $n^{\log_2 2} = n$. Since $f(n) = n^2 = \Omega(n^{1+\varepsilon})$ with $\varepsilon = 1$, $f(n)$ is polynomially larger, so this is **Case 3**.

**Regularity check:** $a f(n/b) = 2(n/2)^2 = n^2/2 \le \tfrac{1}{2} n^2$, so the condition holds with $c = 1/2$.

**Result:** $T(n) = \Theta(n^2)$.

**Exact solution:**

$$T(n) = 2n^2 - n$$

**Proof by induction.**

- **Base case:** $T(1) = 1$, and $2(1)^2 - 1 = 1$.
- **Inductive hypothesis:** assume $T(n/2) = 2(n/2)^2 - n/2 = \frac{n^2}{2} - \frac{n}{2}$.
- **Inductive step:**

$$
\begin{aligned}
T(n) &= 2T(n/2) + n^2 \\
&= 2\left[\tfrac{n^2}{2} - \tfrac{n}{2}\right] + n^2 \\
&= n^2 - n + n^2 \\
&= 2n^2 - n.
\end{aligned}
$$

**Conclusion.** Since $n^2 \le 2n^2 - n \le 2n^2$ for $n \ge 1$, we have $T(n) = \Theta(n^2)$.

---

### Recurrence 3: $T(n) = 4T(n/2) + n$

**Master Theorem.** Here $a = 4$, $b = 2$, so $n^{\log_2 4} = n^2$. Since $f(n) = n = O(n^{2-\varepsilon})$ with $\varepsilon = 1$, $f(n)$ is polynomially smaller, so this is **Case 1**.

**Result:** $T(n) = \Theta(n^2)$.

**Exact solution:**

$$T(n) = 2n^2 - n$$

This is the same closed form as Recurrence 2. It is a coincidence of the base case and constants; the two recurrences are different and are solved by different Master Theorem cases.

**Proof by induction.**

- **Base case:** $T(1) = 1 = 2(1)^2 - 1$.
- **Inductive hypothesis:** assume $T(n/2) = \frac{n^2}{2} - \frac{n}{2}$.
- **Inductive step:**

$$
\begin{aligned}
T(n) &= 4T(n/2) + n \\
&= 4\left[\tfrac{n^2}{2} - \tfrac{n}{2}\right] + n \\
&= 2n^2 - 2n + n \\
&= 2n^2 - n.
\end{aligned}
$$

**Sanity check at $n = 4$:** $T(2) = 4 \cdot 1 + 2 = 6$, $T(4) = 4 \cdot 6 + 4 = 28$, and $2(16) - 4 = 28$.

---

### Recurrence 4: $T(n) = T(n/2) + \log n$

**Why the Master Theorem does not apply.** Here $a = 1$, $b = 2$, so $n^{\log_2 1} = n^0 = 1$. The function $f(n) = \log n$ is larger than $\Theta(1)$, so Case 2 fails, but it is not larger by a polynomial factor $n^\varepsilon$, so Case 3 fails. Case 1 fails as well. The recurrence falls in the gap between the cases, so the basic Master Theorem gives no answer and we use the recursion-tree method.

**Recursion tree.** Let $k = \log n$. At level $j$ ($j = 0, 1, \dots, k-1$) there is one node, of size $n/2^j$, costing $\log(n/2^j) = k - j$. The leaf at level $k$ costs $T(1) = 1$. Summing over the levels:

$$T(n) = k + (k-1) + \dots + 1 + 1 = \frac{k(k+1)}{2} + 1$$

**Result:** $T(n) = \Theta(k^2) = \Theta(\log^2 n)$.

**Exact solution:**

$$T(n) = 1 + \frac{k(k+1)}{2}, \quad k = \log_2 n$$

**Proof by induction on $k$.**

- **Base case:** $k = 0$ gives $T(1) = 1 = 1 + 0$.
- **Inductive hypothesis:** assume $T(2^{k-1}) = 1 + \frac{(k-1)k}{2}$.
- **Inductive step:**

$$
\begin{aligned}
T(2^k) &= T(2^{k-1}) + k \\
&= 1 + \tfrac{(k-1)k}{2} + k \\
&= 1 + \tfrac{k^2 - k + 2k}{2} \\
&= 1 + \tfrac{k(k+1)}{2}.
\end{aligned}
$$

**Conclusion.** Since $\frac{k^2}{2} \le 1 + \frac{k(k+1)}{2} \le k^2$ for $k \ge 2$, we have $T(n) = \Theta(\log^2 n)$.

**Remark (substitution method).** We can also prove the upper bound $T(n) \le 2\log^2 n$ for $n \ge 2$ directly.

- *Base case ($n = 2$):* $T(2) = T(1) + 1 = 2 \le 2 \cdot 1^2$.
- *Inductive step:* assume $T(n/2) \le 2(\log n - 1)^2$. Then

$$
\begin{aligned}
T(n) &\le 2(\log n - 1)^2 + \log n \\
&= 2\log^2 n - 3\log n + 2 \\
&\le 2\log^2 n, \quad \text{since } 3\log n \ge 2 \text{ for } n \ge 2.
\end{aligned}
$$

This agrees with the extended Case 2 from Section 2: here $n^{\log_2 1} = 1$ and $f(n) = \log n = 1 \cdot \log^1 n$, so $k = 1$, giving $T(n) = \Theta(\log^{2} n)$.

## Task 2 & 3: Empirical Measurement and Plots

### Methodology

Two separate programs were used, because they answer two different questions.

**`task2_task3.py`** simulates each recurrence directly: a recursive function that makes $a$ calls on $n/b$ and adds $f(n)$ at the current level, with $T(1)=1$. Since $n$ only ever takes power-of-two values in this experiment, every call eventually resolves to one of about 20 distinct subproblem sizes, so the function is memoized by $n$. Without this, Recurrence 3 ($a=4$) would need $4^{20}$ leaf calls at $n = 2^{20}$, which is not feasible. Because this simulation counts operations purely through the recurrence's own formula, its empirical count matches the theoretical closed form from Task 1 *exactly*, for every $n$ from $2^1$ to $2^{20}$ — this is expected and is really a correctness check on both the simulator and the Task 1 derivations, not a measurement of anything real.

**`task4.py`** instruments actual algorithms whose recursive structure matches each recurrence, with no memoization:

| Recurrence | Real implementation |
|---|---|
| $T(n)=2T(n/2)+n$ | Merge sort (comparisons counted during the merge step) |
| $T(n)=2T(n/2)+n^2$ | Divide-and-conquer with a deliberately brute-force $O(n^2)$ combine (compares every left element against every right element, instead of merging) |
| $T(n)=4T(n/2)+n$ | Pre-Karatsuba recursive multiplication: split two $n$-bit integers into high/low halves, 4 recursive half-size multiplications, $O(n)$ shift-and-add combine |
| $T(n)=T(n/2)+\log n$ | Recursive binary search over the first $n$ elements of a side array, then recurse with $n$ halved |

Because Recurrences 2 and 3 perform genuine polynomial-scale work rather than abstract counting, they cannot be run out to $n=2^{20}$ in Python in reasonable time; their ranges are capped at $n=2^{12}$ (R2) and 1024-bit operands (R3). This cap is itself a small data point for Task 4: it shows the practical cost of an $O(n^2)$ algorithm in a way a Big-O bound alone does not.

An earlier version of the R4 implementation always binary-searched the *full* side array regardless of the current recursion level, which silently simulates $T(n)=T(n/2)+\log N$ for a fixed $N$ rather than the intended $T(n)=T(n/2)+\log n$ — the bound passed to the binary search has to shrink along with $n$. That version also rebuilt the main array at every level via slicing (`arr[:n//2]`), which copies $O(n)$ elements per level and makes the wall-clock time measure array-copying cost rather than search cost. Both are fixed in the version described above (the bound passed to the search shrinks with $n$, and no array is copied at all — only an index is halved).

## Task 4: Critical Analysis

The abstract simulation matches theory exactly for every recurrence and every $n$, because it was built to compute the recurrence's own formula — there is no mechanism by which it *could* deviate. Genuine deviation only appears once a real algorithm is run on real data, which is exactly what `task4.py` is for. Four distinct deviation patterns showed up:

**1. Lower-order terms dominate at small $n$ (Recurrence 1).** Merge sort's leaves cost nothing (the recursion bottoms out and returns immediately — no comparison is made), whereas the recurrence's own base case charges $T(1)=1$. That single difference is exactly the gap: writing $k=\log_2 n$, the empirical count works out to exactly $n\cdot k$, compared to the theoretical $n\cdot k+n$, so the ratio is exactly

$$\frac{nk}{nk+n} = \frac{k}{k+1},$$

which is $1/2$ at $n=2$ ($k=1$) and climbs to $20/21\approx0.952$ at $n=2^{20}$ ($k=20$) — matching the measured values precisely. This is the "lower-order terms" source of deviation named in the brief in its cleanest possible form: the asymptotic bound ($\Theta(n\log n)$) is correct, the gap comes from a single additive term whose relative weight shrinks as $n$ grows, and the exact rate at which it shrinks can itself be written down in closed form.

**2. Constant-factor mismatch between the recurrence's $f(n)$ and the real combine cost (Recurrences 2 and 3).** For Recurrence 2, the brute-force combine step compares every element of the left half ($n/2$ elements) against every element of the right half ($n/2$ elements), which costs exactly $(n/2)^2 = n^2/4$ comparisons — not $n^2$. Carried through the recursion, the empirical/theory ratio converges to a flat $0.25$ rather than $1.0$: both are $\Theta(n^2)$, so the asymptotic *order* is unaffected, but the recurrence's abstract $f(n)=n^2$ overstated the real constant by exactly 4×. The same story applies to Recurrence 3: the real shift-and-add combine touches `half` $= n/2$ bits, not $n$, and the ratio converges to $0.75$. This is the clearest illustration that "$\Theta(n^2)$" is a claim about growth rate, not about the actual number painted on a stopwatch — two implementations can both be $\Theta(n^2)$ and differ by a constant factor that matters enormously in practice.

**3. A bug can look exactly like a deviation finding if you're not careful (Recurrence 4).** An earlier version of the R4 implementation bugs out in a way worth recording rather than papering over: it always binary-searched the *full* side array, not the first $n$ elements of it, so it was silently simulating $T(n)=T(n/2)+\log N$ for a fixed constant $N$ instead of the intended $T(n)=T(n/2)+\log n$. That version's empirical/theory ratio rose from roughly $1.5$ at moderate $n$ (e.g. $n=64$) to about $1.83$ at $n=2^{20}$, and was still rising slowly rather than flat — but it was converging towards $2$, not diverging without bound: with the bug, each of the $k=\log_2 n$ recursion levels costs about $\log_2 n = k$ (not the intended, shrinking $\log_2(n/2^j)$), so the buggy total is about $k\cdot k=k^2$ against the correct closed form's $\approx k^2/2$, and $k^2/(k^2/2)=2$ is exactly the asymptote the ratio was approaching. This at first glance looks like a legitimate "implementation detail changes the constant" story. It is not — it is a mismatch between the code and the recurrence it claims to implement, not a property of the recurrence itself, and framing it as a hardware or constant-factor effect would have been wrong. Once fixed (the search bound shrinks with $n$, exactly as the recurrence requires), the ratio instead fluctuates around $0.9$ with no trend, which is what genuine implementation noise looks like for a recurrence this small (the dominant term is $k(k+1)/2 \approx k^2/2$, so absolute operation counts are only tens to hundreds, and ordinary randomness in where the binary search happens to find its target produces real sample-to-sample variation at that scale). The lesson generalizes beyond this one function: a ratio that keeps drifting in one direction as $n$ grows, rather than settling, is itself a signal worth checking the implementation for — not necessarily evidence of some exotic deviation source.

**4. Overhead and run-to-run variance in wall-clock measurement.** Wall-clock times at the smallest $n$ tested (down to $n=2$) are a few microseconds across all four recurrences — too small and too close to Python's per-call overhead to draw a reliable shape (a "dip" was visible in one run of one recurrence but did not reproduce consistently across repeated runs, so it is not reported as a finding). At the large-$n$ end, repeating Recurrence 1's run three times with different random seeds gave a wall-clock growth factor from $n=2^{16}$ to $n=2^{20}$ of $21.9\times$, $27.3\times$, and $28.5\times$ — consistently somewhat above the $\approx20\times$ that $n\log n$ alone predicts over that range, but not a stable number across trials. This is itself a finding: *operation count* is perfectly reproducible (task2_task3.py's simulation and task4.py's counters are deterministic given a seed), but *wall-clock time* is not, because it also reflects things the recurrence model has no term for — CPython's memory allocator, garbage collection, and OS scheduling noise. Memory-hierarchy effects (the array no longer fitting in cache as $n$ grows past a few hundred thousand elements) are a plausible contributor to the consistent excess over the $20\times$ prediction, but this instrumentation cannot isolate that from allocator/GC overhead without separate profiling — the honest claim is "possibly cache effects, among other overheads we did not separately measure," not a confirmed attribution.

## Task 5: Synthesis — A Modified Recurrence for Uneven Splits and Memory Hierarchy

### Motivation

Real divide-and-conquer algorithms rarely split work perfectly in half, and real machines are not uniform-cost — operating on data that no longer fits in cache is generally believed to cost measurably more per element than operating on data that does. We did not isolate this effect directly: the wall-clock results in Task 4 (point 4 above) show Recurrence 1's measured time growing somewhat faster than $n\log n$ predicts at large $n$, consistently across three repeated trials, but the instrumentation available here cannot separate a cache-miss effect from CPython's allocator or garbage collector. Treat the recurrence below as modeling a plausible real-world effect we did not directly measure, motivated by — but not confirmed by — that observation, rather than as something the Task 4 data proves is happening.

### The recurrence

Consider a divide-and-conquer algorithm that splits its input unevenly — say a 1:3 ratio, which models a partitioning step that is not perfectly balanced (as happens, e.g., with a mediocre but non-adversarial pivot choice) — and that additionally pays a cache-miss penalty whenever the subproblem no longer fits in a cache of size $M$:

$$T(n) = T\!\left(\frac{n}{4}\right) + T\!\left(\frac{3n}{4}\right) + f(n), \qquad f(n) = \begin{cases} n & n \le M \\ c\,n & n > M \end{cases}, \quad c > 1$$

**Solving the uneven split alone ($M=\infty$, no cache penalty).** This no longer fits the Master Theorem (the two subproblems have different sizes), so we use the Akra–Bazzi method: find $p$ such that $(1/4)^p + (3/4)^p = 1$. Here $p=1$ is an exact solution, since $1/4+3/4=1$. Akra–Bazzi then gives

$$T(n) = \Theta\!\left(n^p\left(1 + \int_1^n \frac{f(u)}{u^{p+1}}\,du\right)\right) = \Theta\!\left(n\left(1+\int_1^n \frac{u}{u^2}\,du\right)\right) = \Theta(n(1+\ln n)) = \Theta(n\log n).$$

So an uneven 1:3 split, on its own, does not change the asymptotic order compared to the balanced case $T(n)=2T(n/2)+n$ — both are $\Theta(n\log n)$ — it only changes the constant hidden inside the $\Theta$. This matches the general principle that the Master Theorem's "balanced" assumption is not load-bearing for Case 2-type recurrences as long as the split ratio is fixed and bounded away from 0 or 1; only a split that degenerates as $n$ grows (e.g. $T(n-1)+n$) changes the order.

**Adding the cache penalty — the rigorous $\Theta$ claim.** Rather than argue level-by-level (uneven splits make "all nodes at a level are cold together" false in general, since different branches reach size $M$ at different depths), a sandwich argument gives the asymptotic order cleanly. By construction $f(n)$ satisfies $n \le f(n) \le c\cdot n$ for every $n$ (it equals $n$ when $n\le M$ and $c\,n$ when $n>M$, and $c>1$). Define two auxiliary, memory-oblivious recurrences using the *same* branching structure:

$$T_{\text{lo}}(n) = T_{\text{lo}}\!\left(\tfrac n4\right) + T_{\text{lo}}\!\left(\tfrac{3n}4\right) + n, \qquad T_{\text{hi}}(n) = T_{\text{hi}}\!\left(\tfrac n4\right) + T_{\text{hi}}\!\left(\tfrac{3n}4\right) + c\,n.$$

Both solve to $\Theta(n\log n)$ by the Akra–Bazzi computation above ($T_{\text{hi}}$ is just $c$ times the $T_{\text{lo}}$ recursion, and scaling $f(n)$ by a positive constant scales $T(n)$ by the same constant, leaving the $\Theta$-class unchanged). Since $f(n)$ is sandwiched between the two auxiliary cost functions at every level of recursion, and the recursive structure ($a_i$, $b_i$) is identical in all three recurrences, standard recurrence monotonicity gives $T_{\text{lo}}(n) \le T(n) \le T_{\text{hi}}(n)$ for all $n$. Both bounds are $\Theta(n\log n)$, so

$$T(n) = \Theta(n\log n)$$

follows rigorously, regardless of exactly where the cache threshold $M$ falls or how the cold/warm levels interleave in an uneven tree. The level-by-level cold/warm accounting below is kept only as an approximation for the *constant*, not for the $\Theta$-class itself, which the sandwich argument already settles exactly:

$$T(n) \approx \underbrace{c\cdot n\cdot \log_{4/3}\!\left(\frac{n}{M}\right)}_{\text{cold levels (approx.)}} + \underbrace{1\cdot n \cdot \log_{4/3} M}_{\text{warm levels (approx.)}} = n\Big[c\log_{4/3}n - (c-1)\log_{4/3}M\Big]$$

Two consequences worth stating explicitly, since they are the actual point of this exercise:

1. **The asymptotic class is unchanged** ($\Theta(n\log n)$ either way, proved rigorously above) — this is exactly the limitation of asymptotic analysis the lab is probing. Two algorithms in the same complexity class can behave very differently once $n$ crosses the cache threshold $M$, and no amount of Big-O analysis distinguishes them.
2. **The approximate constant grows with $c$ and with how many levels are "cold"**, which (per the approximation above) predicts a visible "knee" in a plot of time against $n$: roughly linearithmic growth for $n \le M$, then linearithmic growth with a larger effective constant for $n > M$. We have not measured this knee directly — it is a prediction of the model, offered as a plausible explanation consistent with the somewhat-faster-than-$n\log n$ wall-clock growth observed for Recurrence 1 in Task 4, not a confirmed observation. Confirming it would require a dedicated experiment (e.g. varying array size across a known cache boundary while holding the algorithm fixed) which was out of scope here.

## Conclusion

All four target recurrences were solved in closed form and proved by induction: $\Theta(n\log n)$ for Recurrence 1, $\Theta(n^2)$ for Recurrences 2 and 3 (reaching the same order via different Master Theorem cases, and coincidentally the same closed form), and $\Theta(\log^2 n)$ for Recurrence 4, which falls outside the Master Theorem's three cases entirely and required the recursion-tree method instead.

The empirical work makes a point that is easy to state but easy to get wrong in practice: *matching the recurrence exactly* and *matching reality* are different achievements. The abstract simulator in `task2_task3.py` does the former by design — it counts operations straight out of the recurrence's own formula, memoized so the sweep to $n=2^{20}$ is feasible, and so it was never going to show deviation from Task 1's closed forms, only confirm them. The real implementations in `task4.py` do the latter, and three distinct, genuine deviation mechanisms showed up: a lower-order term that shrinks in relative weight as $n$ grows (Recurrence 1, with an exact $k/(k+1)$ closed form for the ratio); a flat constant-factor gap between the recurrence's abstract $f(n)$ and what a real combine step actually costs (Recurrences 2 and 3, converging to $0.25$ and $0.75$ respectively); and wall-clock timing that is not perfectly reproducible run to run, unlike operation counts, because it also reflects interpreter overhead, memory allocation, and (plausibly, though not confirmed here) cache behavior that the recurrence model has no term for.

A fourth, less comfortable lesson came from Recurrence 4: an implementation bug (searching a fixed-size array instead of one that shrinks with the recursion) produced a ratio that drifted steadily with $n$, which superficially resembled a legitimate "implementation changes the constant" finding. Distinguishing a real deviation from a wrong implementation required deriving what the buggy code was *actually* computing ($T(n)=T(n/2)+\log N$ for fixed $N$, not the intended recurrence) rather than accepting the empirical curve at face value. This is itself a finding worth keeping: a monotonically drifting empirical/theory ratio, with no sign of leveling off, is a reason to suspect the implementation before concluding something new about the recurrence.

The synthesis recurrence in Task 5 ties these threads together deliberately rather than decoratively. The uneven 1:3 split is solved with the Akra–Bazzi method precisely because the Master Theorem's balanced-subproblem assumption does not hold for it, and the added cache-miss penalty is solved with a sandwich argument rather than a level-by-level approximation, because an uneven tree makes "every node at a level is cold together" false in general. Both techniques were necessary extensions of what Task 1 covered, applied to a scenario the Task 4 data motivated (the observation, not fully confirmed, that real timing grows somewhat faster than the operation count alone predicts at large $n$). The headline result — that the asymptotic class is unchanged ($\Theta(n\log n)$ either way) while the practical constant can still differ enormously depending on hardware boundaries the recurrence has no visibility into — is the central limitation of asymptotic analysis this lab set out to probe, and the empirical sections give it a concrete, reproducible example rather than leaving it as an abstract caveat.
